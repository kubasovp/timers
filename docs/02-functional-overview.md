## 2.1 Функциональные блоки

### A. Pomodoro
- Профили (create/update/delete, дефолтный профиль).
- Запуск и управление сессией (pause/resume/stop/skip).
- Уведомление о завершении этапа, автопереход между этапами.
- `skip` фиксируется как отдельный статус этапа (не `completed`).
- Одновременно активна только одна pomodoro-сессия.

### B. Кастомные таймеры
- Быстрый запуск по длительности (hh:mm:ss).
- Пресеты с названием/длительностью/описанием/категорией.
- Управление активным таймером (pause/resume/stop/restart).
- Допускается несколько одновременно активных кастомных таймеров.

### C. Напоминания
- Одноразовые, ежедневные, интервальные.
- Управление элементами (enable/disable/snooze/done/delete).
- Обработка пропусков и пересчёт `nextAt`.
- Интервальные напоминания поддерживают пользовательское значение + шаблоны.
- Snooze: выбор из пресетов, один пресет используется по умолчанию.
- При одновременных событиях применяется очередь.

### D. Уведомления
- Системные уведомления для таймеров и напоминаний.
- Звуковой сигнал в MVP обязателен.
- Целевой SLA в MVP: задержка показа уведомления не более 1 секунды от `endsAt`/`nextAt`.

### E. Окно и системный трей
- Разное поведение `X` по платформам.
- Трей (Windows/macOS), Linux-ограничения в MVP.
- Выход при активных сущностях: предупреждение + явное подтверждение.

## 2.2 Системные правила времени (ядро домена)

Чтобы выдерживать сон ОС, лаги UI и перезапуски:
- хранить абсолютные времена (`startedAt`, `endsAt`, `nextAt`), а не только счётчики;
- вычислять остаток как `max(0, endsAt - now)`;
- при старте приложения запускать процедуру `reconcile()`:
  1. пересчитать все активные таймеры;
  2. завершить истёкшие;
  3. сформировать список пропущенных напоминаний;
  4. сдвинуть `nextAt` для повторяющихся правил.

## 2.3 Минимальная модель данных

- `pomodoro_profiles`
- `sessions` (pomodoro/custom)
- `timer_presets`
- `reminders`
- `reminder_occurrences` (история хранится полностью; пользователь может удалять записи вручную)
- `app_settings`
